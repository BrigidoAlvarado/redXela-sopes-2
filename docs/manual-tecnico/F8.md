# F8: API REST y comunicación en tiempo real

Spring Boot expone operaciones en `/api` y un endpoint WebSocket/STOMP en `/ws`. Los controladores invocan los servicios de F1–F7; el navegador no ejecuta planificación, inventario ni detección de deadlock. No se requiere una conexión WebSocket para usar REST.

## Endpoints

| Método | Ruta | Acción |
| --- | --- | --- |
| GET | `/api/simulacion` | Estado, corrida, reloj y factor. |
| POST | `/api/simulacion/iniciar`, `/pausar`, `/reanudar`, `/detener` | Control del motor. |
| PUT | `/api/simulacion/velocidad` | Cambiar `factor`. |
| GET, POST | `/api/clientes` | Listar o crear clientes. |
| GET | `/api/clientes/{id}` | Consultar cliente. |
| GET | `/api/catalogo` | Consultar productos predefinidos. |
| GET, POST | `/api/pedidos` | Listar o crear y admitir un pedido. |
| GET | `/api/pedidos/{id}`, `/api/pedidos/cola` | Detalle/progreso o cola ordenada. |
| GET | `/api/generador` | Estado e intervalo. |
| POST | `/api/generador/iniciar`, `/api/generador/detener` | Control del generador. |
| PUT | `/api/generador/intervalo` | Cambiar `intervaloMillis`. |
| GET | `/api/recursos` | Unidades, disponibilidad y propietarios. |
| GET | `/api/inventario`, `/api/inventario/ubicaciones` | Existencias y ubicaciones. |
| POST, GET | `/api/recepciones`, `/api/recepciones/{id}` | Registrar y consultar una recepción. |
| GET, PUT | `/api/planificacion` | Consultar/cambiar política y aging. |
| GET | `/api/metricas` | Instantánea de F7. |
| POST, GET | `/api/comparaciones`, `/api/comparaciones/{id}` | Iniciar y consultar una comparación. |
| GET | `/api/deadlock` | Estado y conflicto observado. |
| POST | `/api/deadlock/iniciar`, `/api/deadlock/resolver` | Preparar y resolver manualmente. |

Todas las duraciones expuestas usan **milisegundos simulados**, con nombres terminados en `Millis`; el factor es la razón de aceleración. Un tiempo restante o primera atención aún no disponible es `null`. Los productos, niveles y recursos se representan con las enumeraciones del dominio.

Una creación de pedido solo se admite mientras el motor está ejecutándose. La puerta del motor mantiene juntas su creación y admisión respecto de pausa y detención. Si una falla excepcional ocurre después de crear el pedido, la respuesta 409 incluye el ID del pedido creado pero no admitido. Las recepciones devuelven 202 e ID sin esperar a que se almacene el lote.

La comparación devuelve 202 e ID y ejecuta F7 en un único ejecutor dedicado, sin detener el motor principal. `GET /api/comparaciones/{id}` devuelve `EN_CURSO`, `COMPLETADA` con resultado o `ERROR`. Solo se acepta una comparación simultánea; se conservan los 20 resultados más recientes. Para limitar el tiempo de infraestructura, el intervalo solicitado dividido entre el factor no puede superar cinco segundos reales por política; el máximo de observación es 24 horas simuladas y el factor máximo es 1 000 000.

## Ejemplos

Con el servidor en `http://localhost:8080`:

```bash
curl -X POST http://localhost:8080/api/simulacion/iniciar
curl -X POST http://localhost:8080/api/clientes -H 'Content-Type: application/json' -d '{"nombre":"Ana","correo":"ana@ejemplo.com","servicioPreferido":"EXPRES"}'
curl -X POST http://localhost:8080/api/pedidos -H 'Content-Type: application/json' -d '{"clienteId":"UUID_CLIENTE","nivelServicio":"EXPRES","lineas":[{"productoId":"GEN-01","cantidad":2}]}'
curl -X POST http://localhost:8080/api/recepciones -H 'Content-Type: application/json' -d '{"productoId":"GEN-01","cantidad":20}'
curl http://localhost:8080/api/metricas
curl -X POST http://localhost:8080/api/deadlock/iniciar -H 'Content-Type: application/json' -d '{"pedidoA":"UUID_PEDIDO_A","pedidoB":"UUID_PEDIDO_B"}'
curl -X POST http://localhost:8080/api/deadlock/resolver -H 'Content-Type: application/json' -d '{"pedidoGanador":"UUID_PEDIDO_A"}'
```

Sustituir los UUID por los devueltos por la API. Para el conflicto, los pedidos deben estar admitidos y ser elegibles para el escenario de mercancía general; se puede preparar el conflicto antes de recibir sus existencias.

La respuesta inicial de simulación es, por ejemplo:

```json
{"estado":"DETENIDA","corrida":0,"tiempoSimuladoMillis":0,"factorTemporal":60.0}
```

Una solicitud inválida devuelve, por ejemplo, HTTP 400 con `{"codigo":"DATOS_INVALIDOS","mensaje":"Solicitud inválida"}`. Entidades o rutas inexistentes devuelven 404; transiciones incompatibles 409; saturación 429; errores inesperados 500 sin traza en la respuesta. Los errores de servidor se registran en el backend.

## WebSocket y CORS

Conectar con un cliente STOMP a `ws://localhost:8080/ws` y suscribirse a `/topic/estado`. Un único publicador envía aproximadamente cada segundo real un JSON con `simulacion`, conteos de `pedidos`, unidades de `recursos` y estado de `deadlock`. No hay historial ni garantía de entrega de cada instantánea; tras una desconexión el cliente debe reconectarse y suscribirse de nuevo. Las consultas detalladas están en REST.

CORS permite `http://localhost:4200` y `http://127.0.0.1:4200` para la API y la conexión WebSocket. Otros orígenes no están autorizados. La configuración se centraliza en `ComunicacionConfig`.

Ejecutar `./mvnw verify` desde `backend/`; la prueba de integración levanta un servidor local y comprueba HTTP y una suscripción STOMP real. `./mvnw spring-boot:run` inicia la aplicación para las pruebas manuales.
